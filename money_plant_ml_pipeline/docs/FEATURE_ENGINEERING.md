# Feature engineering
All features: sort by (plant_id, timestamp); group by plant; current/past rows only; NaN stays NaN.
* **vpd** (kPa) = es - ea, es = 0.6108 exp(17.27 T / (T + 237.3)), ea = es RH/100. Approximate air VPD, not leaf-level.
* **log_light** = log1p(light). **light_soil_interaction** = log_light / log1p(100000) x soil.
* **soil_rate_per_hr** = soil diff / elapsed hours; elapsed <= 0 -> NaN (never inf).
* **{soil,temperature,humidity,light,vpd}_lag1 / _diff1 / _trend3** (value - value 3 rows ago).
* **_roll{3,6,12}_mean / _std**: trailing windows (`min_periods=1` for mean, 2 for std); never centred.
* **{soil,temperature,humidity,log_light,vpd}_base_dev** = value - mean of the previous 48 observations (excludes the current row; NaN until 6 past rows: warm-up).
* **hour, dayofweek, hour_sin, hour_cos, elapsed_hours** (elapsed_hours not used by the classifier).
* **{soil,temperature,humidity,log_light,vpd}_long{24,48}_mean** (trailing means over 2 / 4 days) and **_long24_dev** = value - mean of the previous 24 observations (the 48-observation deviation is `_base_dev`).
* **Cross-plant: {soil,temperature,humidity,log_light,vpd}_ref_dev** = value - median of the reference plants' readings (`features.cross_plant.reference_plants`, the healthy controls 1-4) and **_ref_dev_roll{3,6,12,24,48}** (trailing per-plant means of that deviation). All plants share one room, so this cancels the common climate, the day-to-day weather and session drift, and leaves the treatment effect. The join is **as-of**: for each row and each reference plant, the latest reading at or before the row's own timestamp, at most 30 min older (`tolerance_minutes`); a plant is never its own reference. A row therefore never sees a later reading of another plant. Plants are read about 45 s apart in each 2-hour slot, so plants 1-2 see each other only, plants 3-4 see three controls and every treated plant sees all four. With no reference reading available the features are NaN and the API adds a warning.
* At inference the reference readings come either from the same frame (training, offline scripts) or from the optional `reference` frame/request field (the API; the backend sends the control plants' readings for the history's time span). Both paths run the same code (`tests/test_features.py::test_separate_reference_frame_equals_training_style_frame`).
History needed for exact parity with full-history features: 49 rows per plant; the API reports 60 (`required_history_rows_for_full_features`) because the temporal smoothing re-predicts the 11 readings before the current one. Tests (`tests/test_features.py`) cover: truncation invariance (no future leakage, also with reference plants), perturbing the future does not change the past, changing reference readings after a time does not change any earlier row, a reference reading even 1 minute after a row is not used, a reference plant is never its own reference, perturbing a non-reference plant does not change this plant, input order independence, zero elapsed time, trailing-not-centred windows, past-only baselines, history-window parity and serving/training parity.

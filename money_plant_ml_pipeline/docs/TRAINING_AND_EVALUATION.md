# Training and evaluation
`python scripts/train_all.py --input <csv>` -> load -> validate (mode from config) -> features -> split -> train A/B/C -> artifacts -> reports.
* **Splits:** `chronological` (default; last 25% of unique timestamps = test) or `group_holdout` (plants 4, 8, 12, 16 unseen). Random splits are intentionally unavailable. The split and cutoff are stored in the manifest and re-used by `evaluate_all.py`.
* **Imbalance:** `classifier.class_weight: none|balanced` (train sample weights only; `balanced` is the default since issue #5). The test set is never rebalanced.
* **Cross-plant features** (`features.cross_plant`): each plant's deviation from the median of the reference plants 1-4 (the healthy controls), taken from their latest readings at or before the row's timestamp (30-min tolerance, as-of join). They are pure transforms with no fitted state, so CV folds need no refit; causality is covered by `tests/test_features.py`. At inference, the reference readings come from the `reference` field of `/predict` or `/predict/batch`, and `/metadata` lists the plants under `cross_plant`.
* **Missing-reference augmentation** (`classifier.missing_reference_augmentation: 0.25`): 25% of the TRAIN rows are added again with the cross-plant features blanked, so a reading without reference context falls back to per-plant features instead of failing. Validation and test rows are never augmented. The same augmentation runs inside every CV fold (`ClassifierSpec.missing_reference_augmentation`).
* **Temporal smoothing** (`classifier.smoothing`): an HMM forward filter over the plant's last 12 predictions. Evidence is (p / prior)^0.3, and the class-transition matrix and prior are fitted on TRAIN labels (consecutive readings of a plant) and stored in `classifier.meta.json` under `temporal_smoothing`. It is past-only and stateless: the service re-predicts the trailing rows from the supplied history, which is why `required_history_rows_for_full_features` is 60. Reported test metrics are smoothed (`metrics`); the single-reading model is kept as `metrics_unsmoothed`. In CV the transitions are fitted per fold on the fold's training labels (`cv_evaluation.smooth_in_fold`), and the filter on test rows starts at each plant's first test reading.
* **Metrics:** accuracy, macro-F1, weighted-F1, balanced accuracy, per-class P/R/F1, confusion matrix, class counts, vs majority-class and logistic-regression baselines.
* **Clustering:** silhouette for each k (sampled to 5,000 rows); limitations in the report.
* **Anomaly:** precision/recall/F1/PR-AUC/ROC-AUC against `is_synthetic_anomaly` on test rows only (label never an input). With few positives (14 in test) these are very noisy.
* **Validation modes** (`validation.mode`): fail, warn, quarantine - see ARCHITECTURE.md.
* **Retraining:** always explicit; each run is a new immutable directory.
* **Cross-validation** (`python scripts/cv_evaluate.py [--candidate reports/tuning/<file>.json]`): the primary metric stays the chronological hold-out (train sessions 1-3, test session 4). Two robustness views are reported next to it, each as mean +- sd across folds (macro-F1, accuracy, balanced accuracy, per-class precision/recall/F1, pooled confusion matrix) with the logistic-regression and majority baselines: leave-one-session-out (folds that train on later sessions are flagged `uses_future_data`) and GroupKFold-by-plant with one plant of every experimental group in each test fold (unseen plants). All preprocessing (imputer, scaler) is fitted inside each fold on its training rows only. Seed noise (about 0.01 macro-F1) is reported as `seed_sd`.
* **Tuning** (`python scripts/tune_classifier.py`): random search over depth, min_child_weight, subsample, colsample, eta, lambda, class weighting and ordinal variants (cumulative binary classifiers, regression with tuned cut-points), early stopping for the number of rounds, selected by validation macro-F1 on inner folds built from the TRAIN sessions only (sessions 2 and 3 as validation). The test session is evaluated once afterwards, for several seeds, against the configured spec; the script only recommends shipping when the mean macro-F1 gain exceeds 0.02 with no loss of balanced accuracy and the winner is inference-compatible (`softprob`). It never edits the config or artifacts. Results of the last run are in `BUILD_REPORT.md`.
* **Issue #5 selection protocol:** feature families, smoothing method and temperature, class weights and the augmentation rate were all chosen on folds inside sessions 1-3: validate on session 2 and on session 3, plus unseen-plant folds restricted to sessions 1-3. Session 4 was used only to confirm the final configuration (3 seeds). `scripts/cv_evaluate.py` reports the configured model with and without smoothing (`xgboost_configured`, `xgboost_configured_unsmoothed`).

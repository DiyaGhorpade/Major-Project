# Money Plant (Tulsi) Monitoring

A dashboard for a 16-pot plant-monitoring rig. A bundled **synthetic** sensor dataset (5,376 readings, 4 sessions,
2 sensor nodes) is stored in a database; one press of **Run** sends every reading through a trained ML pipeline
(stress classifier, anomaly detector, environment clustering, SHAP explanations) and turns the output into
predictions, anomalies and recommendations that every page of the UI shows.

> **Synthetic data.** The dataset and the models trained on it are synthetic, and the stress labels are simulation labels.
> Predictions and recommendations are statistical estimates, not validated plant-health diagnoses. The UI does not repeat
> this on every page (backend/README.md DEV-55); the API still reports it in the `provenance` and `validatedOnRealPlants`
> fields.

## Architecture

| Service | Port | Stack | Role |
|---|---|---|---|
| `frontend/` | 5173 | React 19, Vite, TypeScript | UI; the dev server proxies `/api` to the backend |
| `backend/` | 8000 | FastAPI, SQLAlchemy, SQLite | Seeds the dataset, runs the pipeline, stores results, serves the REST API |
| `money_plant_ml_pipeline/` | 8001 | FastAPI, scikit-learn, XGBoost, SHAP | Prediction / explanation service (HTTP only; the backend never imports it) |

## Quick start

```bash
git clone <this repo> && cd Major-Project
git checkout application          # if it is not your default branch
./scripts/dev.sh                  # Windows: .\scripts\dev.ps1 (untested)
```

Open <http://127.0.0.1:5173> and press **Run** in the top bar. Ctrl-C stops everything.

The first start creates two virtualenvs (`money_plant_ml_pipeline/.venv`, `backend/.venv`), installs the dependencies
(`requirements-tested.txt`, `backend/requirements.txt`, `npm ci`), generates the global SHAP report once, then starts the
ML service (4 workers), backend and frontend. Re-runs skip the installs. Logs are in `.dev-logs/`.

Requirements: **Python 3.12+** (the pinned ML dependencies, numpy 2.5 / xgboost 3.4 / shap 0.54, need it; 3.13 is what they
were tested on), **Node 20+**, npm. Set `PYTHON=/path/to/python3.13` to choose the interpreter.

The trained model artifacts are committed (`money_plant_ml_pipeline/artifacts/`). If you deleted them, `dev.sh` stops and
prints the training command; it never trains automatically:
`cd money_plant_ml_pipeline && .venv/bin/python scripts/train_all.py --input data/raw/plant_sensor_data.csv`.

## What Run does

Before Run, Plants, Data Logs and Sessions already show the dataset; the AI pages show a "Press Run" empty state.
**Run** (`POST /api/pipeline/run`, progress via `GET /api/pipeline/status`) sends all 5,376 readings, each with up to 60
earlier readings of the same plant, to the ML service in batches, stores prediction / anomaly / cluster per reading,
stores SHAP explanations for each plant's latest reading, and builds recommendations from the ML output (each cites the
sensor values and the model probability). On a laptop CPU a first Run takes about **75 s**. Running again is
idempotent: it only predicts what is missing (about 5 s when nothing is). `POST /api/pipeline/run {"reset": true}`
recomputes everything and keeps the status you set on recommendations.

## Make targets

`make setup` (venvs, deps, SHAP report, no servers) · `make dev` · `make test` · `make seed` (DB without servers) ·
`make reset-db` (delete `backend/data/app.db*`) · `make ml-explain` (global SHAP report).

## Tests

`make test` runs backend `pytest` (temporary SQLite DBs, fake ML service; one integration test uses the real ML
service and skips if it is down, so start `make dev` in another terminal to include it) and the frontend `tsc`, `oxlint`,
`vitest` and production build.

## Troubleshooting

- **Port already in use**: `dev.sh` names the port (8000 backend, 8001 ML, 5173 frontend) and exits; stop the other process.
- **Run says the ML service is unavailable / 503**: check `.dev-logs/ml.log`. A numpy/scikit-learn/xgboost version mismatch
  (artifacts were built with the versions in `requirements-tested.txt`) shows up there; recreate the venv with
  `rm -rf money_plant_ml_pipeline/.venv && ./scripts/dev.sh`.
- **Global SHAP page is empty**: the report is generated by `dev.sh` (log: `.dev-logs/explain.log`). Retry with `make ml-explain`.
- **Wrong or missing data**: `make reset-db`, then start again; the dataset is re-seeded.
- **Windows**: `scripts/dev.ps1` mirrors `dev.sh` but has not been run on Windows. WSL2 with `dev.sh` is the safe route.

Source: sample_data_updated.csv (200 stored records). Confirmed architecture: 2 physical ESP32 nodes — Node A (12 plants: Healthy / Water-Stress / Nutrient-Stress) and Node B (4 plants, Light-Stress, remote). The CSV's raw node_id field (NODE‑01…04) are sub-labels from the data run; 3 of them collectively cover Node A's 12 plants and the 4th covers Node B's 4 — shown here regrouped to match the confirmed 2-node topology, with the original sub-id kept visible in the record detail panel. This build runs in Data Replay / Demo Mode — no live ESP32/Jetson connection is wired up, so records are streamed from the stored dataset in chronological order to demonstrate the pipeline end-to-end.
Fields not present in the source data — Sensor_ID, MUX_Channel, Raw ADC — are not shown rather than invented. "OK"/"Check" reflect only whether a record's own fields parsed cleanly. "Anomaly" flags plant IDs that appear under more than one node in the source file — physically impossible for a single wired probe, so treated as a placeholder/junk id rather than a real reading.
